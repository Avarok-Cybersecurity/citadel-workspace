# change to the send path left the stamp unchanged and the gate reported a
# freshly built binary that contained none of it.

# ILM, for the same reason as the connector and by the same route.
#
# The wasm-client depends on the connector, and the connector depends on
# intersession-layer-messaging -- so ILM's source is compiled INTO the binary the
# browser runs. Omitting it meant a change to the reliability layer (the delivery
# frontier, the ack and retransmit logic, the gap tracker) left the stamp
# unchanged, and the gate reported a freshly-built binary that contained none of
# it: precisely the failure described above for the connector, one dependency
# further down.
#

# every ILM change moves it, and nothing else does.
